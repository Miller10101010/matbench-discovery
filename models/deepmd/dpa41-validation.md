# DPA-4.1 OAM：提交与验证说明

本次提交包含 DPA-4.1-Air-OAM、DPA-4.1-Max-OAM 和 DPA-4.1C-Air-OAM。
完整指标、训练信息、环境和文件直链见各模型卡；以下说明截至 2026-10-24 的验证范围。
提交结构参考已合并的 [DPA-4.0.1-Pro-MPtrj PR #341](https://github.com/janosh/matbench-discovery/pull/341)，
格式与检查以当前基准版本 `2b7bff925a6aff10240cf6ef0f59149f51adff7b` 为准。

## 数据和复现材料

| 项目 | 已完成内容 |
| --- | --- |
| 模型卡 | 三份完整 schema；作者、许可证、训练集、checkpoint 参数和训练成本已填写 |

## 网站生成文件

采用仓库官方生成脚本，补充三个模型的 discovery、逐元素误差、热导率和几何图表，
并生成每模型的 energy/kappa parity 压缩数据与两份总清单，共 13 个提交到 Git 的网站文件。
预测文件、模型卡中的科学指标和训练成本保持不变。

基线几何图表记录的 DFT 参考文件 SHA256 为 `d213c0d9…`，当前数据注册表指向的
参考文件为 `eb177c7e…`。官方生成器要求此时使用 `--full-roster`，因此几何共享图表
先以原有 43 模型名单更新参考来源，再独立加入三个新模型；其他图表只加入这三个模型。
原有 43 模型的图表记录逐项保持一致，单独更新参考来源元数据后再追加新模型；没有重新优化结构。

## 前端兼容修复

当前浮动依赖不再从 `matterviz` 导出 HTML 工具和文件下载函数；页面直接从
已安装的 `svelte-widgets` 对应入口导入。旧 main 的同类导入错误已在相同依赖下复现。
另修复空上榜日期被当成 `NaN` 排序的问题：空值仍显示 `n/a`，在两个排序方向均排到已知日期之后。
回归测试包含显式构造的空日期，不依赖当前模型名单是否存在空值；三份模型卡的上榜日期仍保留 `null`。
这部分以独立提交交付，便于与模型结果分开评审。

## 需要评审的数值与来源限制

1. **Air/Max 的短距离双原子异常。** Ne 对 Air 能量／力 MAE 总和的贡献约为
   97.20%／92.44%，对 Max 约为 66.18%／89.73%。固定权重 FP64 诊断仍复现异常，
   原因未定位。全部元素和异常值均保留，没有用诊断曲线替换正式结果。
2. **部分 frozen/eager 检查超出诊断阈值。** 历史 12 元素检查中，Air Ne、Air Kr、
   Max Ne 的力相对 L2 分别为 `1.0789294e-4`、`1.6654274e-4`、`3.0521227e-4`。
   诊断脚本使用 `1e-4` 相对容差并结合绝对容差；这不是已确认的官方拒收标准，
   也没有形成全 92 元素一致性证明。
3. **历史 geometry 信息。** 未记录逐结构 `converged`、`n_steps`，发布 JSONL 保留 `null`；
   历史 cell filter 无法从已提供文件恢复。原始预测能量无缺失；官方预处理屏蔽两个
   极端误差 ID，因此 full set 的 `missing_preds=2`，unique-prototype 子集无缺失。
4. **计时来源。** 三模型均填入 RTX PRO 6000 实测耗时。C 的物理统计来自完整 A800
   研究，成本来自相同 checkpoint 的完整 RTX PRO 6000 重测，分别记录来源。
   C 的 MD `3029.08 s` 是 17 个单 GPU 体系耗时之和；测速源码包含已归档的未提交修改，
   单独一个 commit 号不足以重现该历史运行环境。
5. **可选／维护者数据。** 当前贡献指南不要求外部提交者计算私有标签对应的 MD
   能量／力 RMSE。历史热导率数据没有新版 harmonic `phonon_file`；未补造该可选文件。

这些限制用于判断适用范围；不能从文件格式通过推导出数值问题已经解决。
